WebR Cell Options

Everything you can write after #| in a {webr-r} cell, what each one actually controls, and which one to reach for when a figure looks wrong.

Start here

Three knobs, three different jobs

No, fig-max-height is not something you add alongside fig-width. They are independent, and they fix different problems. Work out which problem you have first.

fig-width / fig-height

Is there blank space inside the picture?

Sets the shape of the canvas ggplot draws on. Fixes empty margins baked into the image. Does not change how big the figure is drawn.

fig-max-height

Is the figure too small on the slide?

Sets how tall the figure may be drawn. Fixes a figure held back by the global 420px cap. Does not remove blank space.

layout / code-track

Is the output cramped next to the code?

Sets where the code and the output sit relative to each other, and how the width is divided between them.

Why you often need two of them. Fixing the canvas shape frees width, and the height cap then becomes what limits the figure. Measured on the map cell in L05_vector_raster_interaction.qmd: fig-width: 3 took the blank space from 44% of the image down to 6.9%, and the map came out at the same 206 × 382 px it was before. Adding fig-max-height: 600 is what took it to 294 × 546.

Figures

Sizing a figure

fig-width fig-height inches default 10 × 6

The canvas ggplot draws on, in inches. This is the fix for blank space inside the image, and nothing else fixes it.

Blank space appears when the shape of your plot does not match the shape of the canvas. It is worst with maps: geom_sf() and geom_spatraster() bring in coord_sf(), which locks the width-to-height ratio so the map is not stretched. ggplot then draws the plot as large as the canvas allows without breaking that ratio, centres it, and leaves the rest of the canvas empty. A tall field on a wide canvas can lose nearly half the image to blank margin.

Aim the canvas at the shape of the content, plus room for the legend.

#| fig-width: 3
fig-max-height new pixels, or none default 420

How tall the figure may be drawn on the slide. This is the per-cell override of the global cap, and the only way to make a figure bigger than every other figure on the site.

The cap exists because nothing else in the chain looks at how much room is left on a slide. A figure asks for the full width of its column and its height follows from the canvas ratio; a 10 × 6 canvas on a full-width slide comes out 603px tall, and a slide is 700px including its title. The cap is what stops a figure pushing its own bottom off the slide.

none removes the limit entirely for that cell.

#| fig-max-height: 600
#| fig-max-height: none

Nothing checks the slide still fits once you have overridden it. Look at the slide afterwards.

out-width percentage default 100%

How much of its column the figure asks for. Leave it at 100%. The height cap is what actually sizes these figures, so a percentage below 100% only ever makes the figure smaller than the cap would have allowed.

dpi number default 216

Canvas resolution. Set once in the deck header and best left alone: the theme block in the deck's setup cell scales ggplot's point and millimetre constants by dpi / 72 to match, and the two have to move together or every line and label comes out the wrong size.

Layout

Where the code and the output sit

Every cell is either stacked, with the output below the code, or side by side, with the output to the right under an Output banner. The choice is made while the page loads and is never revisited, so running a cell can never make the slide reshape itself under a reader.

layout stacked | side default automatic

stacked keeps the output below the code whatever the measurements say, which is how you give a wide printout or a figure the full width of the slide. side asks for two columns.

side is a request, not a command: it cannot make code fit a column that is too narrow for it. stacked always wins, and it is the one to use on a plot cell you want full width, because plot cells are put side by side automatically.

#| layout: stacked
code-track 0.18 – 0.70 default automatic

The fraction of the width the code column takes, with the rest going to the output. Setting it also forces the cell side by side, and turns off every automatic adjustment: the estimate, the re-measurement once the editor has rendered, and the widening that stops a line of code wrapping.

Values are clamped to 0.18–0.70, and the code column never goes below 320px whatever you ask for.

#| code-track: 0.3

What happens without any option

Left alone, a cell goes side by side only if all of these hold:

  • the code is 12 lines or fewer, and no line is longer than 88 characters;
  • the cell is not inside a Quarto .column, which would leave the code a quarter of the slide;
  • the code actually prints something — a cell that only assigns never opens an Output panel that will stay empty;
  • the output measured at render time fits comfortably beside it, and splitting saves enough height to be worth halving the slide.

A cell that draws a plot is put side by side automatically, and a plot in a side column is kept at least 380px wide.

Slides and blocks

Options that live outside the cell

Written on the slide heading or on a fenced div, not after #|
Write thisWhereWhat it does
{.figure-slide} slide heading Raises the figure cap from 420px to 540px for every figure on that slide. For a slide carrying nothing but a figure, where there is no tab bar and the title is one line.
::: {.stacked} around a cell Same as #| layout: stacked, written as a wrapper.
::: {.side-out} around a cell Same as #| layout: side. Also marks the cell as deliberately split, so ordinary measurement noise will not tear the wrapper down.
::: {.side-out style="--webr-code-track: 0.45fr; --webr-output-track: 0.55fr"} around a cell Hand-set the split. Beats every automatic adjustment, same as code-track.

Worked example

A portrait map that was mostly blank

The map cell on the cropping-and-masking slide of L05_vector_raster_interaction.qmd, drawn on the deck's 5 × 4.5 inch canvas. The field is about twice as tall as it is wide, so coord_sf() held the map to a narrow strip and the rest of the canvas was empty.

The middle column is the point worth keeping. Removing the blank space did not make the map one pixel bigger, because once the canvas stopped being wide the 420px cap became what limited it. The two options do genuinely separate jobs.

```{webr-r}
#| fig-width: 3
#| fig-max-height: 600
#| code-track: 0.3
ggplot() +
  geom_spatraster(data = NDRE, alpha = 0.4) +
  geom_sf(data = corn_yield, aes(color = yield), size = 0.05) +
  geom_sf(data = treatment_blocks, color = "red", fill = NA) +
  theme_void()
```
